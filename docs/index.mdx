[**Siglo**](https://github.com/jsoftgem/siglo) is a lightweight, zero-daemon workflow runtime for TypeScript. It orchestrates complex business logic into composable, resilient steps—featuring end-to-end type inference, automatic LIFO Sagas, durable checkpoints, and live visual DevTools without external infrastructure.

### Bi-Directional Code & IDE Visual Inspector Sync

As you author workflows in TypeScript, the **Siglo IDE Visual Inspector** (`@siglo/ide-ui` for VS Code & JetBrains) stays synchronized with your code in real time:

- **Add Steps & Policies in Code -> Instant Graph Update**: Adding `.step(...)`, `.retry(...)`, `.compensate(...)`, or `.timeout(...)` in your workflow file automatically updates the visual DAG and Policy Inspector via `Auto-Reload`.
- **Select a Step in the Visual Tool -> Jump to Code & Open Step File**: Clicking any step node in the visual canvas jumps directly to its `.step()` definition and opens the related step implementation file (`steps/*.step.ts`) alongside its Saga `.compensate()` handler.
- **Place Cursor in Code -> Highlights Visual Node**: Moving your editor cursor inside a step highlights the corresponding node and its active resilience policies in the inspector.

## 30-Second Quickstart

```bash
# Scaffold an interactive runnable project with a deterministic test suite
npm exec --package=@siglo/cli -- siglo init

# Or install directly into an existing service
npm install @siglo/core
```

```typescript
import { Step, flow } from '@siglo/core';

// 1. Define modular steps with input/output contracts
const fetchUser = Step.create('fetchUser', async (param: { userId: string }) => {
    return { name: 'Alice', tier: 'PRO' as const };
});

// 2. Accumulated Context: calculateDiscount automatically receives "tier" produced by fetchUser!
const calculateDiscount = Step.create('calculateDiscount', async (param: { tier: 'FREE' | 'PRO' }) => {
    const discount = param.tier === 'PRO' ? 0.2 : 0.05;
    return { discountPercentage: discount };
});

// 3. Compose into an executable flow
export const orderWorkflow = flow(fetchUser, calculateDiscount);

// 4. Run the flow with full type safety
async function main() {
    const result = await orderWorkflow.run({ userId: 'u_123' }, { pojo: true });

    console.log(result.name); // 'Alice'
    console.log(result.discountPercentage); // 0.20
    console.log(result.$steps.fetchUser); // { name: 'Alice', tier: 'PRO' }
}

main();
```

## Why Siglo? (Comparison Matrix)

| Capability                       | **Siglo (`@siglo/*`)**                                         | Imperative `try/catch` | Temporal                   | Inngest / Trigger.dev       | Effect (`effect-ts`)             |
| :------------------------------- | :------------------------------------------------------------- | :--------------------- | :------------------------- | :-------------------------- | :------------------------------- |
| **External Daemons Required**    | **None** (in-process library; uses your existing DB/Redis)     | None                   | Temporal Server + Workers  | Cloud / Self-hosted Server  | None                             |
| **Step Dispatch Latency**        | **Microseconds** (direct in-memory function call)              | Microseconds           | Milliseconds (gRPC hops)   | Milliseconds–Seconds (HTTP) | Microseconds                     |
| **TypeScript Learning Curve**    | **Standard `async/await`** (`Step.create`, `flow`)             | Standard `async/await` | Deterministic V8 isolate   | Custom step SDK             | Steep FP (`Effect<A, E, R>`)     |
| **Automatic Context Inference**  | **Built-in** (flat accumulated context + typed `$steps`)       | Manual variables       | Manual activity args       | Manual step return wiring   | Generator / pipe wiring          |
| **Declarative LIFO Sagas**       | **Built-in** (`.compensate()` + crash reconciliation)          | Manual reverse `try`   | Manual compensation code   | Manual compensation code    | `Effect.acquireRelease`          |
| **Durable Checkpoints & Waits**  | **Opt-in** (`@siglo/postgres`, `@siglo/redis`, `waitForEvent`) | None                   | Mandatory event sourcing   | Mandatory step replay       | Third-party (`@effect/workflow`) |
| **Static AST & PR Diagrams**     | **Built-in** (`.toMermaid()`, `.toDot()`, VS Code / JetBrains) | None                   | Runtime-only UI            | Runtime-only UI             | None                             |
| **Deterministic `<5ms` Testing** | **Built-in** (`@siglo/testing`, `FakeClock`, `spyStep`)        | Manual Sinon/Vitest    | Heavy test server download | Local dev server required   | `TestClock`                      |

### When to Use Siglo vs. Alternatives

- **Choose Siglo when**:
    - You want resilient multi-step workflows, automatic LIFO Saga rollbacks, retries, idempotency, and durable `waitForEvent` suspensions **inside your existing Node.js/TypeScript services** (Express, Fastify, Hono, Next.js, Kafka, BullMQ, SQS) using the Postgres or Redis you already run.
    - You want **static workflow graph extraction** (Mermaid/Graphviz diagrams in PRs, VS Code & IntelliJ visualizers) and **sub-5ms unit tests** without booting local orchestration containers.
- **Choose Temporal / Inngest when**:
    - You are orchestrating workflows across **polyglot microservices** (e.g., Go -> Python -> Java) or need a dedicated, centrally managed orchestration cluster for multi-month workflows across hundreds of worker fleets.
- **Choose Effect when**:
    - Your team wants a full functional-programming standard library (`Fiber`, `Layer`, `Schema`, `Stream`) across your entire codebase rather than a focused workflow/Saga orchestrator.
